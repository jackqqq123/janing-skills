# Skill creation workflow

1. Select create, improve, review, evaluate, or explicitly approved quick mode.
2. Resolve user/global versus project scope, identify the final absolute target path, and explain project-over-global precedence.
3. Inspect target files, same-name skills, and relevant resources before any change.
4. Collect only missing requirements: task/user, trigger and non-trigger examples, input/output, failure behavior, success assertions, and dependency/permission needs.
5. Draft a concise `SKILL.md` with valid frontmatter and progressive disclosure.
6. Add references for large knowledge and scripts only for deterministic, repeatable local operations.
7. Validate structure and exercise representative prompts.
8. Unless quick mode was explicitly accepted, create the evaluation bundle and report.
9. Obtain an independent subagent audit; repair confirmed findings and re-check.
10. Report final paths, installation precedence, invocation examples, results, and limits.

When a required platform capability does not exist, do not use an ad hoc script, external service, or misleading approximation. Pause for a user-approved technical decision.
